# HMHT 课程版前端需求说明

本文定义 HMHT 课程版简单前端的首版范围。前端只面向课程演示和本地联调，消费现有 Spring Boot REST API，不引入 MQTT、硬件直连、InfluxDB、Python 服务或多运行模式。

## 目标

- 为课程版后端提供可演示的 Web 操作界面。
- 覆盖登录、节点查看、传感器曲线、设备统计、告警、定时任务和个人资料等核心流程。
- 以固定模拟节点 `SIM_Node_01` 为主线组织页面，避免做复杂多租户或真实设备控制能力。
- 保持前端实现简单，优先保证接口联调清晰、状态可恢复、错误提示可理解。

## 用户角色

| 角色 | 说明 | 首版页面重点 |
|------|------|--------------|
| 普通用户 | 使用种子账号或注册账号登录，查看授权节点和个人任务 | 登录、概览、节点详情、曲线、告警、任务、个人资料 |
| 管理员 | 使用种子管理员账号登录，维护节点、用户角色和节点授权 | 首版可隐藏或作为二期；如实现则放在独立管理入口 |

默认账号：

| 类型 | 手机号 | 密码 |
|------|--------|------|
| 管理员 | `13800000001` | `admin123` |
| 演示用户 | `13800000000` | `123456` |

## 首版范围

| 模块 | 页面/能力 | 必做 | 说明 |
|------|-----------|------|------|
| 认证 | 登录 | 是 | 调用 `/v1/auth/login`，保存 token 并进入首页 |
| 认证 | 注册 | 是 | 调用验证码和注册接口，适合课程演示完整流程 |
| 认证 | 忘记密码 | 可选 | 可复用验证码流程，首版时间紧可延后 |
| 首页 | 节点概览 | 是 | 展示当前用户可见节点，课程版通常只有 `SIM_Node_01` |
| 节点 | 节点详情 | 是 | 展示节点状态、传感器元数据、设备元数据 |
| 传感器 | 历史曲线 | 是 | 支持 `temperature`、`humidity`、`light`、`soilHumidity` 和 `24h`、`7d`、`30d` |
| 设备 | 设备统计 | 是 | 展示 `water_pump`、`led_light`、`fan` 的模拟统计 |
| 告警 | 告警列表与处理 | 是 | 支持未处理筛选、分页、处理操作 |
| 任务 | 定时任务管理 | 是 | 支持列表、创建、编辑、删除、启停 |
| 个人 | 个人资料与改密 | 是 | 展示登录用户信息，支持资料修改和密码修改 |
| 管理 | 节点、用户、授权管理 | 可选 | 若课程需要管理员演示，作为后续增强页面 |
| 日志 | 操作日志 | 可选 | 管理员可查看登录、任务、节点等操作记录 |

## 首版不做

- 不做真实设备开关控制或命令下发。
- 不做 WebSocket、Server-Sent Events 或实时推送。
- 不做地图、大屏、摄像头、溯源、聊天、文件上传或头像上传。
- 不做复杂权限系统；前端只按 `profile.role` 控制菜单显示，后端仍是最终校验边界。
- 不做离线缓存或跨设备登录态同步。

## 页面验收标准

| 页面 | 验收点 |
|------|--------|
| 登录页 | 正确提交手机号/密码；失败时展示业务错误；成功后跳转首页 |
| 注册页 | 可获取测试验证码并注册；注册成功后可返回登录 |
| 首页 | 可展示节点列表；无节点、加载中、加载失败都有明确状态 |
| 节点详情 | 可展示节点基本状态、传感器类型、设备类型和阈值 |
| 传感器曲线 | 切换指标和时间范围后重新加载曲线；展示最大、最小、平均值 |
| 设备统计 | 切换设备后展示统计摘要和趋势数据 |
| 告警列表 | 可筛选未处理告警；处理成功后列表刷新 |
| 任务管理 | 可创建、编辑、删除、启停任务；表单校验小时、分钟和重复日期 |
| 个人资料 | 可读取和更新资料；修改密码成功后给出明确反馈 |

## 视觉和交互方向

- 类型：课程演示后台，不做营销落地页。
- 布局：左侧或顶部导航 + 主工作区，优先清晰扫描。
- 信息密度：表格、图表和状态摘要要紧凑，避免大面积装饰内容。
- 颜色：以农业场景的绿色、青色、黄色告警色作为辅助，不让单一颜色支配整个界面。
- 组件状态：每个数据区都需要 loading、empty、error、ready 四类状态。

## 变更同步规则

- 如果前端需要新增或修改后端接口，必须同步更新 `README.md`、`docs/api-endpoints.md` 和 `CHANGELOG.md`。
- 如果前端只新增页面文档或纯前端实现，也需要在 `CHANGELOG.md` 记录本次变更。
- 如果固定节点、传感器类型、设备类型或种子账号发生变化，必须同步更新本文档和相关 API 映射。
